# 项目经验（成功与失败）

## 一、已经做对、必须保持的部分

1. **公式化交付**：所有可计算单元格都用公式或引用联动，没有硬编码结果，LibreOffice 重算后 0 公式错误，1191 个数值与独立复算一致。
2. **口径互相印证**：协方差组合 VaR 与六行业组件 VaR 合计两条路径互相校验，组合分析 B25 与行业风险归因 B42/B43 一致。
3. **难度达标**：模型一 64.9%、模型二 51.8%，都在 65% 以内，且高分值考点集中在真正难以复现的滚动窗口、协方差归因与图表细节上。
4. **题目领域与类型匹配**：经济金融 / 投资 / 股票，任务类型「分析数据 + 呈现洞察」与内容一致。
5. **数据自包含**：所有行情、权重、情景冲击都写在任务文件的「原始行情」「参数设置」里，不依赖外部检索。

## 二、第 1 轮失败原因与教训

### 1. 工作簿外观「AI 感」过重（任务文件）

现象：质检判定「疑似 ai 生成表格」，要求修改表头颜色并去掉内容里的 AI 感。

原因分析：

- 标题行/表头使用了 Office 主题蓝（`#4472C4`、`#1F4E78`、`#5B9BD5`）这类模板默认色，视觉上非常像自动生成的样例文件。
- 表头文字带「股票组合收益与风险分析」这类泛化大标题，以及「蓝色单元格为公式结果；所有收益率、风险指标与贡献值均应保持公式联动。」这类写给执行者看的说明句，像 AI 自述而不是同事留下的台账。
- 颜色语义过强：黄底=待填、浅蓝底=公式结果，一整片色块排列整齐，不像人工制作的业务表格。

教训：任务文件应当像一份内部工作底稿，配色克制（接近灰/深蓝的中性色），只保留必要说明，不要出现劝告式、教学式文字。

### 2. 参考答案改了源文件的背景颜色

现象：质检指出「参考答案修改了源文件的背景颜色，如果 prompt 没有规定请不要修改背景颜色」。

原因分析：参考答案生成脚本用统一的浅蓝 `#EAF2F8` 覆盖了任务文件里已经存在的黄底结果格（如「组合分析」B21、「压力测试」K4），并把 M4 的底色清空。任务文件里已经存在的单元格属于「源文件」，其格式不应被参考答案改写。

教训：凡是任务文件中已存在的单元格，参考答案必须原样保留其填充色、字体与数字格式；新填结果只能用任务文件已建立的同一套样式。

### 3. 参考答案比源文件多出工作表

现象：参考答案有 8 张工作表，任务文件只有 5 张，质检要求把多出的几页补进源文件。

原因分析：脚本在生成任务文件时只写了 5 张表，而参考答案额外新建了「月度收益」「行业风险归因」「风险回测」。模型收到的任务文件里没有这几张表，模型只能凭空新建，评分与被测环境不一致。

教训：**任务文件必须包含参考答案里的全部工作表**，只把「答案单元格」留空。出题时先确定最终工作表清单，再分别生成「空白版」和「填答版」。

### 4. 单元格宽距错误

现象：质检指出参考答案「单元格宽距错误」。

原因分析：列宽只给少数列显式赋值（如「月度收益」只有 A、B 列，「行业风险归因」只有 A、B、I 列），其余列保持默认 8.43 字符宽度；数字列过窄、文本列过宽，日期与金额被挤压。

教训：任何工作表都要为所有用到的列设置明确、适度的列宽，并且任务文件与参考答案在同一张表上的列宽必须一致。

### 5. 评分规则的两处写法问题

现象一：「rubric 里面的错误点是需要写出来具体的正确答案的」。

原因分析：扣分型考点（如「模型输出存在格式或排版错误」「删改了题目没有要求的其他部分」）只描述了错误表现，没有写出正确答案应当是什么，质检无法判定扣分是否公允。

教训：凡是「错误点」型考点，必须在规则正文里写清具体正确答案（正确位置、正确名称、正确格式、正确数值口径），让规则本身可判定。

现象二：「评分这里高中分值占比过高，需要均匀一下分值分布」。

原因分析：32 条规则里 +7～+10 的高分值多达 11 条，中分值 14 条，低分值只有 4 条，分布头重脚轻。

教训：分值要有梯度且均匀分布，把「单元级公式口径」这类可合并的细项适度合并或降档，让高、中、低分值的数量接近均衡，同时保持总分与难度结论不变（模型得分率仍需 ≤65%）。

### 6. 平台自动检测的写法（参考答案位置）

现象：参考答案文件检测报「多个指定区域整体上移一行」，而人工复核认为 A4:A26、B33:G38、B41:B45、J4:L6 等位置与 prompt 一致。

原因分析：检测器把表头行（A3「月末」、B32 行业名、J3「情景」）当作数据行计数，导致整体位移一行的误判。

教训：在 prompt 与参考答案里保持「表头行 + 数据区」的边界清晰可辨，关键区域尽量写成含表头的完整区域描述；对检测器误判要留好人工复核说明，同时避免新增任何真实的位移风险。

## 三、返修执行清单（每轮复用）

1. 用同一份脚本生成任务文件与参考答案，确保工作表清单、列宽、配色、数字格式完全一致。
2. 逐格比对两张表：任务文件里已存在的单元格，参考答案不得改变填充色/字体/格式。
3. 通读任务文件正文，删除教学式、劝告式、AI 自述式句子，配色改为中性。
4. 检查每个工作表的每一列都有显式列宽，日期/金额/百分比列不被挤压。
5. 评分规则：错误点写清正确答案；分值分布均匀；总分与模型得分率仍满足 ≤65%。
6. 提交前重跑三项平台检测，并记录检测结论。
7. 提交后无论通过与否都写一轮总结，沉淀到 `docs/05-修改与提交记录.md`。

## 四、第 2 轮质检暴露的问题（2026-09-22）

第 1 轮的修改方向是对的，但走过了头，第 2 轮又被退回，教训如下。

### 1. 背景色不是「换一种」，而是「基本不要」

第 1 轮把 Office 主题蓝换成中性灰＋米色，第 2 轮仍被判「超出 prompt 要求」：
prompt 只在三处提颜色（「组合分析」Alpha 红黄绿三色条件格式、VaR 贡献数据条、
「风险回测」H4:H14 突破值突出），其余单元格不应有任何自定义底色。

结论：**除了 prompt 明确要求的条件格式，所有单元格一律无填充**。用边框、加粗和数字格式
去表达结构，而不是用色块。

### 2. 字体要「一套到底」

第 1 轮在部分单元格写了深灰字色、米色底配深棕字，造成「字体格式不一致」。

结论：全表统一默认字体与字号（Calibri 11），只有标题/分区/表头加粗；
不要给个别单元格单独设字色或字号。改完用脚本统计一次字体与填充组合，
应只剩「加粗/常规」两种。

### 3. 错误点必须写「错在哪里」，不是「正确答案是什么」

第 1 轮把「错误点」理解成写出正确答案，第 2 轮被要求「具体讲清楚模型错误在哪里，
比如公式的逻辑哪里不对、引用的数据哪里不对、错把 A 当成 B 计算」。

可直接套用的四段式写法：

> **具体单元格** ＋ **模型的实际做法** ＋ **prompt 的要求** ＋ **造成的偏差/后果**

示例（模型在行业归因里把行业收益按等权平均）：
B4:G26 未按 prompt 的「两只成分股按各自目标权重加权后除以行业目标权重(B30:G30)」计算，
模型直接取两只股票收益的均值，导致 B33:G38 协方差矩阵与 I33:K38 组件 VaR 的输入口径错误。

### 4. 分值分布要「三档接近」

第 1 轮把高分值压得太狠（7/15/7），第 2 轮被判「中分值占比过高」。最终采用的分布：

| 区间 | 数量 |
| --- | --- |
| 高（+7～+10） | 10 |
| 中（+4～+6） | 10 |
| 低（+1～+3） | 9 |
| 扣分 | 3 |

调整时把权重挪到模型答不出的难点上，就能同时满足「分布均匀」和「两个模型 ≤65%」。

### 5. 改考点会连带重置检测

只要改动考点内容或分值，「评分规则覆盖度检查」「人机评一致率检测」都会回到待检测状态，
必须重跑；改动分值还会改变「模型得分对比」的分母，需要重新核对 ≤65%。

正确顺序：**改完全部考点与分值 → 保存 → 覆盖度检查 → 人机评一致率检测 → 勾选难度预估 → 提交**。

### 6. 提交校验是逐项的

点击「提交」后平台会依次报出未通过项，实测拦过的有：

1. 「请评估模型一的预估得分是否小于等于 65%」——必须把两个模型的难度预估单选设为「是」。
2. 「评分规则 N 模型 M 未答出的 Sheet 未填写」——凡是判「未答出」的考点，都必须补齐
   「错误工作表名称 / 错误区域 / 错误原因」三要素。

### 7. 编辑时的操作经验

- 平台的「开启工作模式」录屏授权弹窗会周期性弹出并遮住页面，遮罩存在时任何点击都不生效；
  改规则前先确认弹窗不在，必要时刷新页面重新授权。
- 规则表格里的「分值」「答出/未答出」这类下拉框：先点中该控件（点击其显示文本最稳），
  再用方向键调整、回车确认；改动后立刻用解析器复核一次，避免改动没落盘。
- 逐条改完立刻保存，页面长时间停留或刷新会丢未保存的修改。

## 五、出题方法论（沉淀）

1. **先定工作表清单，再写内容**。任务文件与参考答案的工作表必须一致，缺一张就会被打回。
2. **口径写进 prompt，数值写进参考答案**。prompt 只描述算法与位置，不出现任何具体答案。
3. **难度靠「难点考点」而不是「分值堆高」**。把权重放到模型难以复现的地方（滚动窗口、
   协方差归因、条件格式、图表数据源），分数分布自然均匀，两个模型也压得住。
4. **交付前自检三件套**：两张表逐格样式比对、版面（列宽/行高/截断）扫描、公式与关键值复算。
5. **每轮都留档**：质检原文、修改动作、检测结论、模型得分，全部进仓库，下一轮直接复用。
